## 3. Already measured — do not redo

`PLAN-2026-08-17.md` §6 has its own "do not redo" list. These are the 2026-08-17 experiments
behind it. They cost real money; re-running them is waste.

**Judge missingness is fixed.** Per-vendor judge failure rates, vendor errors excluded:

| | W31 | W33 | W34 |
|---|---|---|---|
| worst vendor | 8.0% (Exa) | 17.3% (Exa) | **0%** |
| best vendor | 1.3% | 2.0% | **0%** |
| spread | 6.7pp | 15.3pp | **0.0pp** |

Per-family judge pacing (`5bf7496`) closed it. `c67ac90` adds the detector that was missing.
Note the gate is strict enough that **`2026-W31` would not have passed it** — intended, but
the founder should know a week can now fail for this reason. `P0.3` extends the same floor to
the exporter.

**The rubric is not the cause of the saturation** (`docs/16`). 300 stored W31 responses scored
twice the same day, differing only by an anchored 0–10 band scale. The judges read the anchors
— mean 8.63 → 8.37, share ≥9 69.0% → 56.3%. Nothing that matters moved: **median 9.00 → 9.00,
sd 1.51 → 1.51, ranking identical, 1/4 adjacent pairs separated in both arms, 6/10 of all pairs
in both — the same pairs.** A monotone shift carries no information a ranking can use.

**Harder queries alone do not fix it** (`docs/17`). 240 candidates piloted against Exa and
Serper. Target was a median near 6; the hardest 150 land at **8.50**, against 9.00 for the
standard tier on the same two vendors the same day.

> The kept set's vendor gap of 1.487 vs tier 1's 0.850 **is not a result.** The set was
> selected on low mean score, and selecting on low mean partly selects for high spread.
> Unbiased, all 240 vs tier 1 is **0.850 → 1.092, se 0.174, 95% CI −0.100 to +0.583** — the
> interval contains zero.

Per category: **freshness is the only place these vendors genuinely differ** (`breaking_news`
gap 0.50 → 1.35). `general_facts` is saturated and harder facts do not fix it — retrieving an
obscure-but-documented fact is solved for all five. `long_tail` came out *easier* than the
questions it was meant to beat.

**Carry this forward: difficulty that matters is not obscurity, it is contestability** —
questions where being wrong is possible and detectable. That is exactly what `P2.1`/`P2.2`
(false-premise items) are for.

**Only `2026-W31` can ever be re-judged.** Raw responses live only in `data/vannaris.db`,
which is gitignored; CI runs on a fresh database and destroys them on exit, and
`responses-*.csv` publishes metadata, not result text. W33 and W34 are gone. Any experiment
that re-scores existing data must use W31 (run `50fbea16`, 750 responses with result text).
This is why `P0.8` and `P2.1` are both specified against stored responses.

## 5. Traps — things that look right and are not

- **A weekly run that "succeeded" may have silently skipped the held-out set.** Check the step
  output, not the exit code. Until P0.1's `[C]` half lands this is the likeliest way to lose
  another week.
- **Running `python -m src.export` locally regresses the track record.** The local database
  holds only W31 runs, so the exporter rebuilds W31 from it and carries W33/W34 forward from
  committed JSON. On a stale checkout this silently produced `weeks_published: 2,
  scheduled_weeks: 0, schedule_started: false`. It happened on 2026-08-17 and was caught by
  `git diff`. Pull first; diff `site/data/bundle.js` before committing anything generated.
- **Nothing gates `schedule_started` against regression.** The only references are in
  `scripts/make_fixture_db.py`. A bad export would publish it.
- **`export.canonical_run` picks one run per week by completeness**, so any ad-hoc run landing
  in `runs` for the current week can displace the scheduled one and flip `trigger` to `manual`.
  This is why `experiments/pilot_v3.py` writes nothing to the database. Keep it that way.
  `P0.4` hardens the related `--rejudge` week-stamping hazard.
- **A wrong `gold_answer` inverts a grade rather than adding noise** — the rubric shows it to
  the judge as "Known correct answer". Three of the 240 candidates had garbled golds on the
  first draft, one carrying a false premise. Validate any authored batch before piloting.
- **A gold containing "latest" or "current" decays** into a general-knowledge question within
  weeks. `breaking_news` carries no gold at all for this reason, and `P2.3` (freshness
  rotation) depends on keeping it that way.
