## 1. What I verified, and where it differs from the audit

Read directly: `src/runner.py`, `src/judge/ensemble.py`, `src/heldout.py`, `src/export.py`
(pricing/track-record sections), `scripts/check_keys.py`, `scripts/check-all.sh`,
`.github/workflows/{weekly,heartbeat}.yml`, `LICENSE-DATA`, `README.md`, the W33 export, the
labels, and the uncommitted site diff.

**Confirmed as described:**

- `runner.py:551–553` — `persist()` runs only after `judge_all()` returns. A crash or the 90-minute
  timeout mid-judging discards the run *and* the `--rejudge` path with it. Largest structural gap.
- `ensemble.py:391–406` — `_retry_after` treats every 429 identically. Worse than the audit says:
  the family limiter is held *across* retries (`ensemble.py:447`, deliberately), so a
  quota-exhausted key can hold 1 of OpenAI's 3 slots for up to ~4 × 70 s.
- `scripts/check_keys.py:132–157` — the judge probes send `max_completion_tokens` / `maxOutputTokens`
  only. No `temperature`, no `seed`, no `response_format`, no `thinkingConfig`. A model that rejects
  any of those passes preflight and fails 100 % of judging.
- `weekly.yml` never calls `check-all.sh`. The publishing path runs `check_vendors` + `check-site` +
  `check-quality` and skips: unit tests, `check-structure`, the labeller gate, `heldout_committed`,
  forbidden-claims, the labels gate, the calibration-not-published-early gate, and the staged-secrets
  gate.
- `weekly.yml:72–74` still says "750 vendor calls and 2,250 judgements".
- `PRICING` (`export.py:99–115`) is hand-maintained with no freshness marker.
- `judge_model_returned` is stored per row and never compared to the pin.
- No `robots.txt`, no `sitemap.xml` under `site/`.
- `README.md:177` claims "$55–70/month all in, measured rather than estimated".
- W33: `n_heldout_queries: 0`, `heldout: null`, `trigger: "manual"`, completeness 89.3 %, OpenAI
  coverage 0.893 (670/750) against 0.996 for the other two.
- The uncommitted redesign strips `#vendors`, `#finding`, `#picks`, `#prior`, `#limits`, the
  leaderboard table and four figures from the landing page — and removes **Methodology, Data and
  Source from the nav**, which the audit does not mention and which is the sharpest part of it.

**Five things the audit does not say:**

1. **The held-out diagnosis is essentially closed.** `ho-2026-08` is registered, active, 30
   questions, text present locally, hash verifies. `heldout.cmd_install` prints "`SB_HELDOUT_JSON`
   is empty — the public set will run alone" and **exits 0**. W33 was committed by
   `vannaris-runner` on Actions. So: the Actions secret is almost certainly unset. It is one
   founder action, not an investigation.
2. **`first_week` is never written.** `cmd_commit` writes `None`; nothing else touches it. The
   4-week rotation has no mechanism behind it, and `heldout.sets[].first_week` will publish as
   `null` forever even after the set runs. Fix by deriving it in the export, not by editing the
   manifest (`AUTONOMY` item 9 forbids that).
3. **The working tree is not green.** `check-structure.mjs` fails on the redesign's snapshot drift.
   257 unit tests, `check-site` and `check-quality` pass. The redesign cannot land as-is regardless
   of the design decision.
4. **`heartbeat.yml` already exists** — Monday 14:00 UTC, compares the published week against the
   calendar and names the 60-day cron suspension in its own failure text. The audit's cron concern
   is half-covered; the remaining hole is that heartbeat is *itself* a cron workflow.
5. **The README cost figure is not currently derivable.** Judge token counts are stored per score
   row but never exported, so neither `$55–70` nor `~$24` can be checked from published data.
