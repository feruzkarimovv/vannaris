## 1. Verdict

The harness is trustworthy. The ranking is not.

This is an unusually honest measurement pipeline that currently cannot tell its
top two vendors apart, ties on 74% of queries, and has never run the held-out
set it advertises. A blinded human already separates 96% of the pairs the
ensemble calls ties. The work is to give the published table a score that can
actually rank — not to polish more decimals on a ceiling.

Citeable ranking needs three things at once: items where being wrong is
possible, a score that records that wrongness, and uncertainty that matches
the resolution of the data. Vannaris has the third in prototype (paired CIs +
tiers) and is missing the first two.

## 3. Scoring pipeline (what the code actually does)

```
query (public set, held_out=0)
  → vendor adapter → raw_responses (content never published)
  → 3 judges (Anthropic / OpenAI / Google), pointwise rubric
  → judge_scores: relevance, freshness, citation_quality, overall (0–10)
  → response score = median(overalls) iff all 3 present
  → cell = mean(response medians) in (vendor, category); null if coverage < 0.60
  → vendor overall = mean of published category cells (equal category weight)
  → ranking = sort by overall descending
  → tiers = paired mean-diff 95% CI vs tier leader (Z = 1.96)
  → publish via export recomputed from judge_scores (weekly_scores ignored)
```

The exported field `"t"` on a paired comparison is `mean / se`. It is a **z**,
not Student’s t. `weekly_scores.median_score` stores a **mean** of per-response
medians. `paired_difference` and `build_tiers` have **no unit tests**.

Dimensions are stored and written to CSV. Ranking uses only `overall`.

Gold answers exist on 75 / 150 queries (`general_facts`, `multi_hop`,
`code_technical`) and are injected as “for your reference.” There is no
exact-match, checklist, URL-hit, or nDCG scorer. Schema column `gold_urls` is
unused in production (0 queries populate it). `rotates=1` is stored on 25
breaking-news questions and never acted on.

Held-out set `ho-2026-08` is hash-committed
(`9f77dad6f65736801ee4db64e1fc05a1477059caa2685a3c39e0c38a200d47f5`, n=30).
`heldout install` still exits 0 when `SB_HELDOUT_JSON` is empty. Every
published week has `n_heldout_queries: 0` and `heldout: null`.

### 4.5 Measured causes, not guesses

- **`docs/16`.** Strict rubric anchors moved the mean −0.26 and left median,
  SD, ranking, and which pairs separate unchanged. The queries bind, not the
  wording of the 0–10 scale. Do not ship anchors alone as a discrimination fix.
- **`docs/17`.** 240 “harder” candidates, kept 150, median still **8.5**
  against a target of ~6. Unbiased vendor-spread gain vs the current set:
  +0.24, SE 0.174, CI includes zero. Selecting on low mean inflates spread.
  **Do not promote that set.**
- **Near-ties.** Humans split 48 / 50 pairs the ensemble scored level. Vendors
  are distinguishable. The published scale cannot see it.
- **Leave-one-out.** On W34, dropping Google or Anthropic swaps first place.
  The published #1 is an ensemble artifact.

### 4.6 Three remaining difficulty levers (`docs/17`, untested)

Same-style harder facts are a dead lever. In this order:

1. **False-premise questions**, with a rubric clause, measured as its own
   change. Deliberately excluded from the v3 batch.
2. **Rebalance toward freshness** (the only v3 category that moved) and away
   from `general_facts`. Implement the `rotates` flag that currently does
   nothing.
3. **Comparative judging** as a second arm, not a replacement. `docs/04`
   rejected full pairwise on cost, not on discrimination. At five vendors, one
   within-query ranking call per judge is +100% judge cost, not 4×.

If a hard tier ever lands: two tables, never blended. Headline stays the
standard 150 so W31+ remains comparable.

## 5. What a real ranking needs here (and what not to cargo-cult)

| Property | Today | Needed | Do not cargo-cult |
|---|---|---|---|
| Primary metric | Mean of category means of 0–10 overall | Multi-metric: overall + dimensions + gold-hit rates, never blended into one mystery number | A single Elo replacing the table |
| Separation | Wald z on paired mean diffs; adjacent pairs only; no FDR | Bootstrap (or Wilcoxon) CIs; full C(5,2) matrix; effect size; multiplicity control | p-value stars on a saturated scale |
| Rank uncertainty | Point sort, then collapse to tiers | CI on the overall score and on the rank / tier itself | Pretending five distinct ranks exist |
| Items | 150 documented, answerable questions; `general_facts` at 9.7 | Contestable items: false-premise, live freshness with rotating gold | Obscure Wikipedia facts (v3 already failed this) |
| Objective check | Gold is a prompt hint on half the set | Atomic fact containment + `gold_urls` hit@k as a parallel track | Classic BEIR nDCG as the headline (closed corpus) |
| Human audit | One labeller, pairwise, 79% on decisive pairs | Second labeller (IAA); keep saying absolute 0–10 is unaudited | Publishing model-vs-model as calibration |
| Overfit check | Held-out registered, never run | 30 questions every week; gap CI after ≥3 weeks | A secret score nobody can recompute |
| Comparative scoring | Pointwise only | Secondary arm: within-query forced rank, sampled, with order swap | Full pairwise of 8–9 vendors in the main loop |

Keep everything that already makes this honest: paired (not unpaired)
comparisons, tiers instead of fake 01–05 badges, published disagreement
including the 9–13% of responses that split judges by more than 3 points,
leave-one-out robustness, payload-length diagnostics, persist-before-judge,
quota vs rate-limit, missingness spread gate, cadence copy derived from
`runs.trigger`, COI policy that names the savings-share conflict. None of that
is optional. None of it creates a ranking on its own.
